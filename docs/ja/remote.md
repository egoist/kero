# リモートホスト

Kero は、Linux の開発マシン、クラウドの VM、机の下の Mac mini、WSL ディストリビューションなど、ほかのマシンで動くセッションを、ローカルのセッションと同じウインドウに表示できます。同じサイドバー、状態表示、通知、`kero` コマンドが使えます。各マシンはそれぞれの kerod を動かすので、ノートパソコンを閉じても Kero を終了しても、ローカルと同じようにリモートのエージェントは動き続けます。

## クイックスタート

ホストとは、Kero が入っている任意のマシンです。すでに Kero アプリを使っている別のコンピュータでも、ディスプレイのないサーバーでもかまいません。

### Kero アプリが入っているコンピュータ

アプリのほかに何もインストールする必要はありません: アプリ自身の kerod がホストとして働きます。ほかのマシンからの接続方法を選びます:

- **Tailscale 経由。** ホスト側のアプリで **設定 › ホスト › ほかのマシンからの接続を許可** をオンにします。ほかのマシンで追加するアドレス（`http://studio.tail1234.ts.net:7373` など）が表示されます。[Tailscale](#tailscale) を参照してください。
- **SSH 経由。** そのコンピュータが SSH ログインを受け付けるなら（Mac では **システム設定 › 一般 › 共有 › リモートログイン**）、`ssh` に渡すのと同じアドレスで追加します。Kero はそこにあるアプリを自分で見つけます。

自分のコンピュータと同じように、ホストのセッションはアプリを閉じている間も動き続けます。

### サーバー

Linux マシン、クラウドの VM など、アプリのないマシンには、サーバー版の Kero をインストールします。root や管理者権限、ディスプレイ、GTK は不要です。Linux や macOS では:

```sh
curl -fsSL https://github.com/egoist/kero/releases/latest/download/install-server.sh | sh
```

Windows では、PowerShell で:

```powershell
irm https://github.com/egoist/kero/releases/latest/download/install-server.ps1 | iex
```

### ホストを追加する

自分のコンピュータで **設定 › ホスト** を開き、ホストのアドレス（SSH なら `me@devbox`、またはホストのアプリに表示されたアドレス）を入力して **追加** を押します。ホストのプロジェクトが、それぞれホスト名付きで、あなたのプロジェクトと一緒にサイドバーに表示されます。

コマンドラインでも同じことができます:

```sh
kero hosts add devbox me@devbox
kero -H devbox new -n review -- claude
```

::: tip
追加したホストに Kero がインストールされていなければ、サイドバーにそう表示され、**Kero をインストール…** が提案されます。これは SSH でホスト上に上のスクリプトを実行します。
:::

## Kero がホストに接続する方法

アドレスは、ホストへの接続方法を示します。設定、設定ファイル、`kero -H` の後で、Kero は同じアドレスを受け付けます。

| アドレス | 方法 |
| --- | --- |
| `devbox`、`me@devbox`、`me@devbox:2222`、`ssh://me@devbox` | `~/.ssh/config`、キー、エージェントを使った SSH |
| `wsl://Ubuntu`、`wsl://` | この Windows PC の WSL ディストリビューション（`wsl.exe` 経由） |
| `http://devbox:7373` | tailnet アドレス上の kerod のリスナー（[Tailscale](#tailscale) を参照） |
| `https://devbox.tail1234.ts.net` | Tailscale Serve の背後にある kerod |

Kero はホストごとに 1 本の接続を開き、すべてをそこに載せます: サイドバーの状態、表示しているすべてのペイン、CLI のコマンド。接続は圧縮され、ハートビートが切れた接続を数秒で検知します。ノートパソコンのスリープなどで接続が切れると、ホストのセッションは薄く表示されたままサイドバーに残り、Kero は自動で再接続します。再試行の間隔は最大 1 分まで延びていきます。

### SSH

SSH では、Kero はホスト上で `kero __bridge` を実行します。これは、kerod が動いていなければ起動し、接続をそこに渡します。ホストには Kero 自体（アプリかサーバー版）のほかに何もセットアップする必要はなく、ネットワークで待ち受けるものもありません。

アプリには答える人がいないので、Kero は SSH で何かを尋ねることはありません:

- **パスフレーズ付きのキー** には SSH エージェントが必要です。Kero は、ターミナルの `ssh` と同じく、シェルが `SSH_AUTH_SOCK` に設定したエージェント（1Password のものなど）を使います。
- **初めて接続するホスト** は、先にそのキーを信頼する必要があります。ターミナルで一度 `ssh me@devbox` を実行してください。
- **パスワードログイン** には対応していません。キーを使ってください。

Kero は、ホスト上の `kero` を `~/.local/bin`（Windows では `%LOCALAPPDATA%\Programs\kero-server`）、デスクトップアプリとそのコマンドラインツール、`PATH` から探します。ほかの場所にある場合は、アドレスで指定します: `me@devbox?kero=/opt/kero/kero`、Windows なら `me@pc?kero=C:/kero/kero.exe`。

### Windows ホスト

Kero は SSH で Windows マシンに接続するので、先に OpenSSH Server をオンにしてください（管理者として **設定 › システム › オプション機能**）。Kero は、サーバーのデフォルトのシェルである cmd と、PowerShell のどちらでも動きます。どちらなのかは最初の接続時に調べるので、その接続には少し時間がかかります。

インストールスクリプトは、kerod をタスクスケジューラのあなたのタスクとして登録し、マシンにログオンしたときにあなたのセッションで起動します。誰もログオンしていない間は、Kero が接続したときに kerod が起動し、接続が終わった後も動き続けます。そのように起動した kerod は、キーを使った SSH のプログラムと同じく Windows のパスワードなしで動くので、そのセッションのプログラムはネットワーク共有や、Windows が保存している資格情報にアクセスできません。アカウントのすべての権限で動かすには、一度マシンにログオンするか、ログオン後に kerod を再起動してください。

### WSL

Windows では、`wsl://Ubuntu` で、SSH と同じようにその WSL ディストリビューションにインストールされた Kero に接続します。`wsl://` はデフォルトのディストリビューションです。そこに Kero がインストールされていなければ、SSH のときと同じくインストールを提案します。

WSL は、Windows から起動した最後のプログラムが終わってしばらくすると、ディストリビューションを停止することがあり、kerod も一緒に止まります。エージェントを動かし続けるには、たとえば [systemd を有効にして](https://learn.microsoft.com/windows/wsl/systemd)その中で `kero daemon install-service` を実行し、ディストリビューションを起動したままにしてください。

### Tailscale

kerod は tailnet で待ち受けることもでき、その場合 SSH はまったく不要です。誰が接続しているかは Tailscale が kerod に伝え、デフォルトではマシンを所有する Tailscale ユーザーだけが入れます。アプリのあるホストでは、**設定 › ホスト › ほかのマシンからの接続を許可** をオンにすると、ほかのマシンで追加するアドレスが表示されます。サーバーの場合や手で設定する場合は、ホストの設定に次を追加します:

```ini
# ホスト上の ~/.config/kero/config
listen = tailnet://:7373
```

その後、ホストを `http://devbox:7373` として追加します。接続はプレーンな HTTP ですが、tailnet のデバイス間では WireGuard が暗号化します。

代わりに Tailscale の証明書を使って HTTPS で提供するには、kerod にソケットで待ち受けさせ、Tailscale Serve をそこに向けます:

```ini
listen = tailnet-serve://
```

```sh
tailscale serve --bg --https=443 unix:$HOME/.config/kero/serve.sock
```

その後、ホストを `https://devbox.tail1234.ts.net` として追加します。ソケットは Kero のデータフォルダにある `serve.sock` です: Linux では `~/.config/kero`、macOS では `~/Library/Application Support/kero`。

所有者以外の接続を許可するには、`listen-allow` に列挙します: tailnet のログイン、タグ付きデバイスなら `tag:ci`、tailnet 上の誰でもなら `*`。タグ付きのマシンには所有者がいないので、`listen-allow` だけが接続を許可します。Tailscale Serve はタグ付きデバイスが誰なのかを kerod に伝えないので、それらは `tailnet://` リスナーに接続します。

```ini
listen-allow = alice@example.com
listen-allow = tag:ci
```

kerod は `listen` と `listen-allow` の変更に追従し、オフにしたリスナーはそれが受け付けた接続を切ります。kerod の動作中に追加した `tailnet-serve://` リスナーは、`kero daemon restart` まで待機します。kerod が待ち受けるのは設定で求められたときだけで、Tailscale 上だけです。Web ブラウザからのリクエストは拒否するので、訪れた Web ページから接続されることはありません。インターネットからの Funnel のリクエストは決して入れません。マシンの起動とともに待ち受け続けるには、サービスとして実行してください（下記）。

## kerod をサービスとして実行する

アプリのあるホストでは、アプリを開いたときか、Kero が SSH で接続したときに kerod が起動します。サーバーでは、kerod を自分のサービスとして実行すると、マシンの起動とともに開始し、誰もログインしていない間もセッションを動かし続けられます。インストールスクリプトがこれを行います。Mac では、サービスは launchd エージェントで、Mac にログインしている間だけ動くので、ログインしたセッションを残しておいてください（ログインしていればスクリプトがインストールします）。Windows では、ログオン時に kerod を起動するタスクスケジューラのタスクです。

```sh
kero daemon install-service      # systemd ユーザーユニット、macOS では launchd エージェント、Windows ではタスク
kero daemon status               # 動作の仕方と、待ち受けている場所
kero daemon uninstall-service
```

Linux では、まず lingering（`loginctl enable-linger`）を有効にします。これにより、ログアウト後もサービスが動き続けます。これがないと、最後の SSH セッションが終わったときにサービスが止まってしまいます（必要に応じて起動した kerod はそれより長く動きます）。そのため `install-service` は lingering なしでは先に進みません。lingering に管理者の許可が必要なシステムでは、管理者に `sudo loginctl enable-linger <you>` を実行してもらうか、`--no-linger` を付けてサービスをインストールしてください。

`kero daemon serve` は、独自のサービスマネージャ向けに、kerod をフォアグラウンドで実行して標準エラーにログを出力します。アイドルを理由に終了することはありません。`--listen` は設定の `listen` キーの代わりになります。

## ホストで作業する

- **サイドバー。** プロジェクトを、あなたのものを先に、次に各ホストのものを **設定 › ホスト** の順に一覧します。ホストのプロジェクトには `api` `devbox` のように名前の後にホスト名が付くので、2 台のマシンの同じリポジトリが並んで表示されます。ホスト専用の行が現れるのは、あなたの対応が必要なときだけです: Kero が接続できないとき、アップデートが必要なとき、インストールされていないとき。セッションのないホストは表示されません。プロジェクトを開くでそこにセッションを開始してください。ホストのプロジェクトを右クリックすると、ホストのメニューが開きます: 再接続、kerod の再起動、Kero のアップデート、カラー、ホストの設定。
- **カラー。** 各ホストには名前から選ばれたカラーがあります: サイドバーのタグとペインのヘッダーのホスト名にその色が付くので、リモートのペインがひと目でわかります。ホストのメニューの **カラー** か、アドレスの後の `color=`（`host = devbox=me@devbox color=teal`）で別の色を選べます。
- **新規セッション。** <kbd>⌘</kbd> <kbd>T</kbd> と **新規セッション** は、表示中のセッションのホストでセッションを開始します。プロジェクトの **+** は、そのマシンのそのプロジェクトでセッションを開始します。
- **プロジェクトを開く。** ホストを追加していると、<kbd>⌘</kbd> <kbd>O</kbd> はコンピュータのダイアログの代わりに Kero の中でフォルダを一覧し、表示中のセッションのマシンから始めます。上部の切り替えで別のマシンのフォルダを一覧できます。入力して絞り込むか、`~/code` のようなパスを入力します。<kbd>↩</kbd> でフォルダの中に入り、<kbd>⌘</kbd> <kbd>↩</kbd> か **開く** でプロジェクトとして開きます。
- **パス。** リモートのペインでファイルパスを <kbd>⌘</kbd> クリックすると、下のペインでホストの `$EDITOR` でそのファイルを開きます。フォルダはそこで新しいセッションとして開きます。Kero が、たまたま同じパスにあるあなたのコンピュータのファイルを開くことはありません。画像のパスに <kbd>⌘</kbd> を押しながらポインタを合わせると、ホストの画像をプレビューします。
- **画像とファイルのペースト。** リモートのペインに画像やファイルをペーストすると、ホスト上の非公開の一時フォルダにコピーされ、そのパスがペーストされます。Claude Code のように画像のパスを読むエージェントも、そのまま動きます。ファイルをリモートのペインにドラッグした場合は、あなたのコンピュータのパスがペーストされます。
- **エージェント。** リモートのペインの中では、`kero` はそのホストの kerod と通信するので、エージェントのスキルはそのまま動きます。ホストで `kero skill setup` を実行してください。
- **通知。** ホストの通知とウインドウのタイトルにはホスト名が付くので、リモートのプログラムがローカルのものになりすますことはできません。

### リモート操作

`kero focus` と `kero do` を使うと、プログラムがアプリを操作できます。ホストの場合、それは別のマシンのコードがあなたのコンピュータのウインドウを操作することになるので、デフォルトではオフです。**設定 › ホスト** でホストごとにオンにするか、アドレスの後に `remote-control` を付けます:

```ini
host = devbox=me@devbox remote-control
```

### 設定

外観、キーボード、通知はアプリの設定です。ホストのシェル、`env`、スクロールバック、セッションの復元は、kerod がそこで読み込むので、そのホストの設定から来ます。変更するには、ホストで `kero config edit` を実行してください。

## バージョンとアップデート

アプリとホストは、異なるバージョンの Kero を実行できます。ホストがアプリより古いリリースを実行していると、サイドバーのその最初のプロジェクトに **アップデート** が表示されます。これは、アプリのバージョンの Kero をホストにダウンロードし、そのバージョンとプラットフォームについて Kero 自身のアップデートの署名に使われるキーで検証してから、そこで kerod を再起動します。再起動するとホストのセッションは履歴とともに元の場所から再開し、そこで実行中のプログラムは終了するので、Kero は先に確認します。

- Kero がホストをアップデートするのは、あなたが求めたときだけです。再接続時には行わず、古いバージョンに戻すこともありません。
- ホストがアプリより新しい Kero を実行しているときは、代わりにアプリをアップデートしてください（**設定 › 一般**）。
- Kero がアップデートするのは、インストールスクリプトでインストールしたものです。ホストに別の方法で Kero をインストールした場合は、インストールしたときと同じ方法でアップデートしてください。
- Kero デスクトップアプリを実行しているホストは、許可すればほかのマシンからアップデートを受けられます: そのコンピュータで **設定 › ホスト › ここの Kero のアップデートを許可**（`remote-updates = true`）をオンにします。するとそこのアプリは最新のリリースにアップデートし、再起動して、kerod を再起動します。それまでは、そのコンピュータでアップデートしてください。

コマンドラインから:

```sh
kero -H devbox version           # この kero のバージョンと、ホストのバージョン
kero -H devbox daemon status
kero -H devbox daemon update     # この kero のバージョンへ
kero -H devbox daemon restart
kero daemon update               # ホスト上で、最新のリリースへ
kero daemon update 2.1.0         # ホスト上で、指定したバージョンへ（古いものも可）
```

## コマンドライン

コマンドの前の `-H`（または `--host`）は、セッションに対するコマンドをホストの kerod に向けます。ホストの名前、アドレス、またはこのマシンを示す `local` を受け付けます。`$KERO_HOST` も同じですが、ペインの中では `kero` はペイン自身のマシンに対して動きます。`kero config` や `kero hook` のようなこのマシンだけのコマンドは、`$KERO_HOST` を無視します。

```sh
kero hosts                       # 追加したホスト（JSON なら --json）
kero hosts add build ci@build.lab --remote-control
kero hosts check build           # 接続して結果を表示。名前かアドレス
kero hosts install build         # SSH か WSL でそこに Kero をインストール
kero hosts remove build
kero -H build ls
kero -H build prompt review "run the tests and fix them"
kero clients                     # このマシンの kerod に接続しているもの
```

アプリと CLI は、ひとつのホストのリスト、つまり設定の `host` キーを共有します:

```ini
host = devbox=me@devbox
host = build=ssh://ci@build.lab:2222 remote-control
host = ubuntu=wsl://Ubuntu
```

| 変数 | 働き |
| --- | --- |
| `KERO_HOST` | `-H` と同じく、コマンドを向けるホスト |
| `KERO_SSH` | `PATH` にあるものの代わりに Kero が実行する `ssh` プログラム |
| `KERO_RELEASES` | インストールスクリプトと `kero daemon update` 用の、Kero のリリースのミラー |

## セキュリティ

- **接続は、そのアカウントにできることは何でもできます。** ローカルの接続と同じく、プログラムの起動も含みます。SSH では、SSH がログインさせるあなた自身のアカウントです。Tailscale では、マシンの所有者が許可した人だけです。
- **ソケットはあなた専用です。** kerod のソケットはそのユーザーだけが読める状態で作られ、kerod はほかのユーザーのプロセスからの接続を拒否します。
- **アップデートは署名されています。** サーバー版は、Kero のリリースのキーで署名されたアーカイブからのみ自分をアップデートします。
- `kero clients` は、kerod に接続しているものを、その接続方法とともに一覧します: `uid 501 over unix`、`me from 10.0.0.5 over ssh`、`alice@example.com over tailnet`。

## 制限

- サーバー版は、glibc 2.28 以降の Linux、macOS、Windows 10（1809）以降の、x86-64 と ARM64 に対応しています。Kero アプリのあるマシンにはサーバー版は不要です。
- ファイルをリモートのペインにドラッグすると、あなたのコンピュータのパスがペーストされます。代わりにペーストしてください。
- 1 つのホストには 1 つのアカウントです。複数の人が 1 台のマシンでそれぞれのアカウントに接続するログインサーバーには、今後対応する予定です。
