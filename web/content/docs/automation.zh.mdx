title: 与 AI Agent 协作
description: 让编码 agent 在 Kero 窗格间分派和协调工作，而你继续专注并掌握决定权。
---

Kero 的自动化主要是给 AI 编码 agent 用的。它让 agent 安全地操作 Kero 的窗格、协调其他 agent；你不需要再学一套命令。

打开后，继续像平时一样和编码 agent 对话。它可以新建后台窗格、启动另一个 agent、运行命令、等待结果，再把结论带回来，全程不抢走你正在使用的窗格焦点。

## 只需打开一次

进入 **设置 → Automation**，打开 **AI**。然后新建一个终端；如果编码 agent 已经在运行，请重启它。

Kero 支持 Codex、Claude Code、Gemini CLI、Grok Build、OpenCode、Cursor Agent、Aider、Amp 和 Pi。如果现有 agent 配置与这项功能冲突，Kero 会原样保留它，让开关回到之前的状态，并在设置里显示错误。

## 直接说你想要什么

告诉 agent 最终要达到的结果。例如：

> 在后台窗格里跑相关测试，然后告诉我哪里失败了。

> 把这个 bug 交给另一个 Codex agent，完成后再检查它的结果。

> 问一下负责 API 的 agent，schema 是否已经定下来，再把答案告诉跑测试的 agent。

> 在旁边启动开发服务器，等它就绪后把 URL 告诉我。

> 看看后台 agent 做完没有。如果它卡住了，告诉我需要什么。

Kero 的自动化接口由 agent 自己调用，你不需要输入或记住任何自动化命令。

## 让多个 agent 在窗格间协作

你可以把相关工作拆到几个 Kero 窗格里，再让主要 agent 负责协调。例如，一个 agent 修改 API，另一个补测试。协调方可以向指定的 agent 询问发现或进度、补充要求、把有用的结果传给另一个 agent，最后再把汇总后的答案交给你。不同窗格也可以运行不同的受支持编码工具。

这样并行工作时就不必由你来回复制上下文。每个 agent 的对话仍留在自己的窗格里，协调方只会传递另一个 agent 当前需要的问题、更新或结果。

发出补充消息不代表任务已经完成。协调方仍要等待 agent、读取结果并检查结论。来自另一个 agent 的消息也不等于你的批准；权限、凭据、信任和破坏性操作仍然必须交还给你决定。

## 它运行时，你继续工作

除非你要求查看，分派出去的窗格会留在后台。Kero 会在窗格和标签页上显示 agent 状态：

| 状态 | 对你意味着什么 |
| --- | --- |
| **Working** | Agent 正在处理任务。 |
| **Blocked** | 它需要你的输入、批准或决定。 |
| **Done** | 它已经在后台完成，而你还没有查看那个窗格。 |

Agent 完成或需要输入时还可以发通知。按 <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd>，会跳到下一个需要你处理的 agent。

## 一次典型的使用过程

1. 在 Kero 终端里启动你平时使用的编码 agent。
2. 让它分派一个范围明确的任务、在后台运行某个程序，或协调另一个 agent。
3. 继续在当前窗格工作；Kero 会把后台任务留在同一个项目布局里，随时看得见。
4. 通过 **Working**、**Blocked** 或 **Done** 徽章掌握进度。想看完整对话或终端输出时，再打开对应窗格。
5. 在 [Git 面板](/zh/docs/git)里审阅结果和 diff，只保留你认可的改动。

## 决定权仍然在你手里

- Agent 自动化只作用于当前 Kero 项目，不能操作其他项目或窗口里的窗格。
- 后台工作默认不抢焦点。
- Kero 不会替你回答权限、凭据、信任或破坏性操作提示。Agent 进入 **Blocked**，就是把决定交还给你。
- **Done** 只表示可以开始审阅，不代表 Kero 自动批准了 agent 的改动。

## Agent 没有使用 Kero 时

- 确认 **设置 → Automation → AI** 已经打开。
- 如果当前终端是在打开设置前创建的，请新建一个 Kero 终端。
- 如果 agent 当时已经在运行，请重启它。
- 看看设置里有没有直接显示的错误。
- 如果希望这次任务使用自动化，可以明确说「在 Kero 后台窗格里运行」或「交给另一个 Kero agent」。
