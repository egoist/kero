title: Settings
description: Themes, fonts, and every key in Kero's config file.
---

Open Settings with <kbd>Cmd</kbd>+<kbd>,</kbd>. Everything in the window is
written straight to a plain TOML file, so you can also edit it by hand or keep
it in your dotfiles.

## Appearance

**Theme** — follow macOS, or force Light or Dark. The three previews are
miniature Kero windows painted in the real colors.

## Colors

Two pickers, one per appearance: a **dark theme** and a **light theme**. Kero
switches between them as the appearance changes.

The list is Kero's own Default plus the entire bundled Ghostty theme catalog —
485 of them. A theme recolors the terminal, the window chrome, the sidebars, and
the editor together, live, with no relaunch.

<Callout type="info">
The built-in Defaults keep Kero's GitHub-derived palette and its translucent
sidebar. Every other theme colors the sidebar to match as well.
</Callout>

## Font

- **Family** — JetBrains Mono is bundled and used by default; any installed
  fixed-pitch family can replace it.
- **Size** — 8 to 32 points.
- **Thicken font strokes** — heavier glyph strokes, like classic macOS font
  smoothing. Off by default so text matches a stock Ghostty install.

The preview underneath exercises regular and bold text plus Nerd Font symbols,
so you can see whether your prompt's icons survive the change.

The same font is used by the terminal, the editor, and the diff viewer.

## Terminal

**Restore session history on relaunch** — reopened terminals show their previous
scrollback above a `Session Contents Restored` divider, with a fresh shell below
it. Off by default, because turning it on means captured terminal output is
written to disk.

## Text Editing

**Wrap lines to editor width** — off by default, so long lines scroll
horizontally instead.

## Updates

**Automatically check for updates** and a **Check for Updates…** button. See
[Installation](/docs/installation#updates).

## Reset to Defaults

Puts every setting above back where it started. It doesn't touch your projects,
sessions, or window layout.

## The config file

```
~/.config/kero/config.toml
```

Kero writes this file whenever a setting changes, and only records values that
differ from the default — a config with nothing unusual in it is nearly empty.

| Key | Type | Default | What it does |
| --- | --- | --- | --- |
| `theme` | `"system"` \| `"light"` \| `"dark"` | `"system"` | Appearance override |
| `theme-dark` | string | Kero's dark default | Color theme used in dark appearance |
| `theme-light` | string | Kero's light default | Color theme used in light appearance |
| `font-family` | string | bundled JetBrains Mono | Terminal, editor, and diff font |
| `font-size` | number | `13` | Point size, 8–32 |
| `font-thicken` | bool | `false` | Heavier glyph strokes |
| `editor.wrap-lines` | bool | `false` | Soft-wrap editor lines |
| `terminal.restore-history` | bool | `false` | Restore scrollback on relaunch |

```toml title="~/.config/kero/config.toml"
theme = "dark"
theme-dark = "Catppuccin Mocha"
font-family = "IBM Plex Mono"
font-size = 14
terminal.restore-history = true
```

An unknown theme name falls back to the default rather than leaving the picker
blank, so a typo won't lock you out of the settings window.

<Callout type="warn">
Debug builds read `~/.config/kero-dev/config.toml` instead, so running one
alongside an installed Kero won't overwrite your real settings.
</Callout>
