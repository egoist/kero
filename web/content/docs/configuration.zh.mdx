Kero 能改的一切都在一个文件里：

```
~/.config/kero/config.toml
```

设置窗口（<kbd>Cmd</kbd>+<kbd>,</kbd>）写的是同一个文件，用哪个都行——这个文件不是退而求其次
的后门，设置本来就在这里。Kero 的全部选项都列在下面。

## 这个文件的行为

手动改之前值得先知道：

- **启动时读一次。** Kero 运行中改文件不会有任何变化，得重启。在设置窗口里改则立即生效。
- **只要有设置变化，Kero 就会重写它。** 文件是从头重新生成的，所以你**写的注释和 Kero 不认识
  的键都会丢**——只要你下次在设置窗口里动了任何一个控件。二选一，或者把权威版本放在你的
  dotfiles 里，让它覆盖过来。
- **只写非默认值。** 一份没什么特别配置的文件几乎是空的。删掉某个键就恢复它的默认值，删掉
  整个文件就全部恢复。
- **解析器很小。** 支持扁平键（`font-size = 14`）、点号键（`editor.wrap-lines = true`）、
  `[table]` 表头（会被摊平成点号形式）、`#` 注释，以及字符串 / 数字 / 布尔值。不支持数组、
  内联表和多行字符串。
- **错误的值会被忽略，而不是报错。** 超出范围的字号或拼错的主题名会退回默认值，而不是让程序
  起不来。

## 外观

### `theme`

`"system"` · `"light"` · `"dark"`——默认 `"system"`

Kero 用哪种外观，和 macOS 其余部分无关。`"system"` 跟随系统一起切换；另外两个把 Kero 钉死在
一种外观上，不管系统在做什么。

它决定的是下面**哪一个**配色主题生效——它本身不是配色选择。

### `theme-dark` 和 `theme-light`

字符串——默认 `"Default Dark"` 和 `"Default Light"`

两种外观各自使用的配色主题。Kero 始终同时持有这两个并在它们之间切换，所以跟随系统就意味着
夜里是深色、白天是浅色，你什么都不用动。

换主题会同时给终端、窗口装饰、侧边栏和编辑器重新上色，即时生效。可用的名字是：

- `"Default Dark"` 和 `"Default Light"`——Kero 自己的，源自 GitHub 的配色。只有这两个保留半透明
  侧边栏；其余每个主题都会把侧边栏刷成不透明，以匹配自身。
- **内置 Ghostty 主题目录**里的任意一个，用它的确切显示名：`"Catppuccin Mocha"`、
  `"Gruvbox Dark Hard"`、`"Tokyo Night"`、`"Nord"`、`"Solarized Dark"` 等等。匹配是精确的，
  区分大小写。

认不出来的名字会静默退回默认值——这也是为什么一个笔误不会让你在设置里对着一个空选择器发呆。

没有什么拦着你把深色主题写进 `theme-light`。Kero 不会纠正你；只是设置里的选择器不会给你这个
选项，因为它按背景明度把主题目录分成了两半。

```toml
theme = "system"
theme-dark = "Catppuccin Mocha"
theme-light = "Catppuccin Latte"
```

## 文字

### `font-family`

字符串——默认 `""`，即内置的 JetBrains Mono

凡是显示文字的地方用的都是它：终端、编辑器和 diff 视图都读这一个键，所以 diff 绝不会用和
产生它的那个 shell 不同的字体来显示。

Kero 内置 **JetBrains Mono**，并且只为自己这个进程注册它，不会往系统里装任何东西。它还挂了
**Symbols Nerd Font** 作为后备，所以哪怕你选的字体不是打过补丁的 Nerd Font，powerline 分隔符和
图标字形也能正常显示。不管你这里设成什么，这个后备都在。

写字族名，不要写具体字重：`"IBM Plex Mono"`，不是 `"IBM Plex Mono Regular"`。不存在的名字或者
非等宽字体会退回内置默认值，而设置窗口本来就只列出等宽字族。

### `font-size`

数字，8–32——默认 `13`

磅值。超出范围的值会被丢弃，改用默认值。

这是唯一一个即使等于默认值 Kero 也照写不误的键。

### `font-thicken`

布尔值——默认 `false`

用更粗的笔画渲染终端字形，就像经典的 macOS 字体平滑那样。默认关闭，这样文字和原版 Ghostty
一致。

在非 Retina 屏上值得一试，那里默认的字看着可能偏细。在 Retina 屏上它基本只会让文字变糊。

### `editor.wrap-lines`

布尔值——默认 `false`

在[文件编辑器](/zh/docs/files)里把长行按窗格宽度软折行。关闭时它们改为横向滚动。

只影响编辑器——终端里怎么折行是运行中的程序的事，而 diff 视图始终是滚动的。

## 终端

### `terminal.restore-history`

布尔值——默认 `false`

Kero 重启时恢复每个终端之前的滚动缓冲区，位置在新启动的 shell 上方、`Session Contents
Restored` 分隔线下方。

它默认关闭，理由值得直说：打开它意味着 Kero 会捕获终端输出并**写到磁盘上**，以便之后重放。
如果有密钥从你的终端里过，它也会进到那个文件里。

回来的是静态文本——是「当时发生过什么」的记录，不是一个活着的会话。
[项目、标签页和窗格布局](/zh/docs/projects#重启后还剩下什么)无论如何都会恢复；这个选项只管
它们里面的滚动缓冲区。

## 一份完整的例子

```toml title="~/.config/kero/config.toml"
theme = "dark"
theme-dark = "Catppuccin Mocha"
theme-light = "Catppuccin Latte"
font-family = "IBM Plex Mono"
font-size = 14
font-thicken = false
editor.wrap-lines = true
terminal.restore-history = true
```

每个键都是可选的，而这就是全部了。没出现在这份列表里的东西，Kero 就是不让你配。

## 不在这个文件里的东西

- **自动检查更新。** **设置 → Updates** 里的那个开关属于 Sparkle，存在 macOS 的偏好设置里，
  不在这儿。见[安装](/zh/docs/installation#更新)。
- **窗口和布局状态**——窗口尺寸、侧边栏宽度、当时开着哪个面板、用来恢复项目的会话快照。它们都在
  macOS 自己的偏好设置里，归属 `sh.kero`，也不适合手动改。
- **Ghostty 的配置。** Kero 不读 `~/.config/ghostty`。终端内核是 libghostty，但它的设置就是上面
  上面这些键；其余一切都用 Ghostty 的默认值。
- **快捷键。** 目前[快捷键](/zh/docs/shortcuts)是固定的。
