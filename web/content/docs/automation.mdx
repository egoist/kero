---
title: Working with AI agents
description: Let coding agents delegate work and keep parallel sessions in sync while you stay focused and in control.
---

Kero's automation is primarily for AI coding agents. It gives them a safe way
to work with Kero's panes and coordinate other agents; it is not another
command language you need to learn.

After you enable it, keep talking to your coding agent normally. It can create
a background pane, start a delegated worker, run a command, wait for the
result, and bring the answer back without taking focus from the pane you are
using.

## Turn it on once

Open **Settings → Automation** and enable **AI**. Then start a new terminal or
restart any coding agent that was already running.

Kero supports Codex, Claude Code, Gemini CLI, Grok Build, OpenCode, Cursor
Agent, Aider, Amp, and Pi. If Kero finds an existing agent setup that conflicts
with this feature, it leaves that setup unchanged, returns the toggle to its
previous state, and shows the error in Settings.

## Ask in plain language

Tell your agent the outcome you want. For example:

> Run the focused tests in a background pane and tell me what fails.

> Delegate this bug to another Codex agent, then review its result.

> Ask the Claude session working on the API whether the schema is ready, then
> pass the answer to the test session.

> Start the dev server beside us, wait until it is ready, and give me the URL.

> Check whether the background agent is finished. If it is blocked, tell me
> what it needs.

The agent handles Kero's automation interface on your behalf. You do not need
to type or memorize any Kero automation commands.

## Let parallel sessions keep each other in sync

With [Claude Code 2.1.224 or later](https://code.claude.com/docs/en/cross-session-messaging),
Claude sessions running on the same Mac can pass findings, questions, and
status directly to each other. You can ask one session to check on another,
or let a session warn a peer when its work changes a shared API or unblocks a
dependent task.

This removes the copy-and-paste step from parallel work. Each conversation
stays visible in its Kero pane while the agents exchange only the text they
need. They do not share conversation history or files.

A message from another agent is never treated as your approval. It cannot
answer a permission prompt, change configuration, or bypass the receiving
session's normal safety rules. If the next step needs your decision, the agent
still becomes **Blocked** and hands it back to you.

## Keep working while it runs

Delegated panes stay in the background unless you ask to see them. Kero shows
the agent's state on its pane and tab:

| State | What it means for you |
| --- | --- |
| **Working** | The agent is actively handling the task. |
| **Blocked** | It needs input, approval, or another decision from you. |
| **Done** | It finished in the background and you have not viewed the pane yet. |

An agent that finishes or needs input can also send a notification. Press
<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>A</kbd> to jump to the next agent that
needs your attention.

## A typical workflow

1. Start your usual coding agent in a Kero terminal.
2. Ask it to delegate a bounded task, run something in the background, or
   coordinate another agent.
3. Continue working in your current pane while Kero keeps the delegated work
   visible in the project layout.
4. Follow the **Working**, **Blocked**, or **Done** badge. Open the pane when
   you want the full conversation or terminal output.
5. Review the resulting files in the [Git panel](/docs/git), inspect the diff,
   and decide what to keep.

## You stay in control

- Kero's pane automation stays inside the current project and cannot operate
  panes in another project or window. Claude Code's own session messaging has
  separate controls. By default, agents use it only for related sessions in
  the current project; another project is contacted only when you name that
  target.
- Background work does not take focus unless you explicitly ask for it.
- Kero never answers permission, credential, trust, or destructive-action
  prompts for you. A blocked agent hands that decision back to you.
- Completion is a signal to review the result, not an automatic approval of
  the agent's changes.

## If an agent does not use Kero

- Confirm that **Settings → Automation → AI** is enabled.
- Open a new Kero terminal if the current one existed before you enabled the
  setting.
- Restart an agent that was already running when you enabled it.
- Check Settings for an inline setup error.
- Ask explicitly for a "background Kero pane" or a "delegated Kero agent" if
  you want the agent to use this workflow for a task.
- For Claude-to-Claude updates, use Claude Code 2.1.224 or later and keep the
  target session running.
